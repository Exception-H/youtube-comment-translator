# 评论译读 · YouTube 中文评论

版本：1.5.0。可直接加载到 Chrome 的 Manifest V3 扩展。

1.5.0 新增 **中英双搜**：在 YouTube 原搜索框直接输入中文并提交，结果页由扩展接管为左中文、右英文两栏；右栏在后台用 B站免 Key 的 Index-Translate 把中文搜索词翻成英文再搜一次，并把右栏可见的英文视频标题翻成中文，保留「查看英文原标题」。它只处理含中文的搜索词，英文搜索仍走 YouTube 原生结果。

评论翻译的主推荐仍是 **B站 Index-Translate · 官方免费公网 API**：不用登录、不用注册、不需要 API Key。原来的 Google 免密钥翻译、硅基流动（SiliconFlow）零价模式、OpenRouter 仅免费模式、DeepSeek 和自定义 OpenAI 兼容接口都保留，但不再作为默认推荐。升级不会强制切换 provider，也不会把旧配置改成 B站。

安装包为 `评论译读-Chrome-v1.5.0.zip`，从 [GitHub Releases](https://github.com/Exception-H/youtube-comment-translator/releases/latest) 下载。也可以下载仓库源码，直接加载其中的 `extension` 目录。

## 已安装用户如何更新

1. 解压 `评论译读-Chrome-v1.5.0.zip`。
2. 用解压后 `extension` 文件夹中的文件，覆盖原先已加载的 `extension` 文件夹内容。保留原文件夹路径，可以保留扩展设置。
3. 打开 `chrome://extensions`，在「评论译读」上点击「重新加载」。
4. 刷新 YouTube 标签页。
5. 如果评论翻译已经在用 B站预设，**不需要重新填 Key，也不需要重新授权 B站来源**。如果还没授权中英双搜，打开扩展选项页的「中英双搜」区域（`options.html#dual-search`），点击「授权中英双搜」，允许访问 `https://index-translate.bilibili.com/*` 即可。

相对 1.4.0，本版**没有新增 manifest 权限**；新增的是扩展内部的内容脚本、样式和后台搜索桥接文件。正常覆盖并重新加载不会新增权限提示；如果 Chrome 显示了权限变化，请先核对 ZIP 来源和文件内容。

如果原来直接加载的是本项目目录下的 `extension`，只需重新加载扩展并刷新 YouTube。

**升级不会自动迁移旧配置。** 已有的硅基流动或 OpenRouter 配置保持原样，不会被改成 B站预设，也不会自动切换 provider；旧 Key 只留在它对应的服务配置里。需要 B站免费接口时，请手动选择该预设并保存。新安装时 AI 设置页默认展示 B站预设，但总开关的 provider 仍是 `google`；只有手动选择「AI 语境翻译」并保存后才会启用 AI，升级同样不会自动把 provider 改成 AI。

## 首次安装

解压安装 ZIP，在 Chrome 的 `chrome://extensions` 中开启右上角「开发者模式」，点击「加载已解压的扩展程序」，选择 **extension** 文件夹。该文件夹内直接包含 `manifest.json`。安装后刷新 YouTube 页面，向下滚动到评论区。

不要直接把 ZIP 拖进 Chrome。加载后请保留 `extension` 文件夹。支持 Chrome 109 及以上，主要面向电脑端 `www.youtube.com`。

## 中英双搜（1.5.0）

### 怎么用

1. 在 YouTube 原搜索框输入中文，照常提交。扩展不改写搜索框，也不要求先翻译。
2. 进入 `/results` 后，如果搜索词含中文，页面原来的结果区域会被替换为「中文结果 / 英文结果」双栏。
3. 左栏使用你输入的中文搜索词；右栏在后台把中文搜索词翻成英文，再用英文搜索，并把右栏可见的英文标题翻成中文。
4. 右栏标题翻译成功后，旁边会出现「查看英文原标题 / 收起英文原标题」，可随时展开原文；翻译失败时可单独重试。
5. 结果页顶部 masthead 有「中英双搜」开关。关闭后立即移除自绘双栏，恢复 YouTube 原生结果；重新开启后再次接管。

只有**含中文字符**的搜索词会触发。纯英文、纯数字或其他语言的搜索词保持 YouTube 原生结果，不额外请求 B站。英文栏显示的是「英文检索词返回的 YouTube 结果」，**不保证视频内容、字幕或音轨是英语**。

### 默认值与独立性

- `settings.dualSearch` 默认为 `true`，但它**独立于评论翻译**的 `settings.enabled` 和 `settings.provider`。
- 打开中英双搜不会修改评论翻译服务，不会读取评论翻译的 Key，也不会要求你填写 Key。
- 暂停或关闭 AI 评论翻译，不影响中英双搜；反过来关闭双搜，也不影响评论翻译。
- 默认开启只代表页面会尝试接管；**只有取得 B站来源权限后才会发送搜索词/标题翻译请求**。没有权限时，左栏中文结果仍可正常使用，右栏会提示去设置页授权。
- 已经为评论翻译授权过 `https://index-translate.bilibili.com/*` 的用户，无需重新授权；同一来源权限会被复用。

### 布局与分页

- 宽屏下左右两栏并排，**各自独立滚动**，互不影响。
- 每栏到底后通过 YouTube 的 continuation 继续加载；可以使用「加载更多」，滚动到底也会自动加载。
- 窄屏下改为「中文结果 / 英文结果」标签页切换；切换标签时会保留各栏原来的滚动位置，不会跳回顶部。
- 两栏的加载、错误和重试互不阻塞。某一栏失败时只在该栏显示错误和「重试」，另一栏继续可用。

### 结果如何显示

- 每个栏内按 11 位 video ID 去重，同一栏不会重复插入同一个视频。
- 两栏之间不做去重：如果同一个 video ID 同时出现在中文和英文结果中，会保留在各自栏内，并标记「两路均命中」。
- 每栏保持 YouTube 自己返回的顺序，不重新按相关度排序，也不把两栏强行对齐。
- 自绘列表只渲染可识别的视频与 Shorts 条目。频道、课程、播放列表、电台以及已知广告槽位不纳入自绘列表；YouTube 未来新增的类型也可能暂时不被识别。
- 不保证两栏的条目数量、顺序或内容一致，也不保证翻译后的英文检索词能覆盖所有相关视频。

### 请求方式

- 初次搜索和后续分页都向**当前页面同源**的 `/youtubei/v1/search?prettyPrint=false` 发送 `POST`。
- 初次请求体包含页面公开的 `clientName`、`clientVersion`、`hl`、`gl` 四个字段，以及 `query`，并在原 URL 带 `sp` 时一并携带；分页请求使用 continuation token。
- 这些字段从页面已公开的脚本配置中读取，**不硬编码 YouTube 客户端版本**；continuation token 只保存在内存中。
- 扩展代码**不读取** YouTube 的 Cookie、Authorization、visitorData 或 apiKey，也不会调用 YouTube Data API，不需要 YouTube API Key。
- 但这是浏览器同源请求：Chrome 会按 YouTube 的正常规则带上你现有的 YouTube Cookie。因此它**不是匿名请求**，YouTube 会像看待当前网页会话的一部分那样收到正常连接信息。扩展不读取这些 Cookie，也不会把它们发给 B站。
- 不打开隐藏标签页，不复制整页 HTML，不发送浏览历史。

### 发送给 B站什么

中英双搜只使用固定的 B站免 Key 服务与固定模型 `Index-Translate-35B-A3B`，与评论翻译当前选择的 provider 无关。

发送给 B站的只有：

- 你输入的中文搜索词（用于翻成英文检索词）；
- 右栏**可见**英文视频标题，以及作为理解上下文的中文搜索词（用于翻成中文标题）。

不发送 YouTube URL、视频 ID 列表、完整页面、浏览历史、continuation token、YouTube 客户端配置或 Cookie。请求不带认证、不带 Key，使用 `credentials: 'omit'`、`referrerPolicy: 'no-referrer'`、`redirect: 'error'`。针对 B站官方端点的精准 `Origin` 移除规则沿用 1.4.0，只作用于本扩展发往该端点的 POST。

### 翻译节奏、缓存与超时

- 搜索词翻译优先，右栏拿到英文检索词后才发起英文搜索；标题只为**当前可见**的条目排队，滚动后再翻译新进入视口的标题，以减少请求。
- 搜索词和标题翻译与评论翻译共用同一个固定 B站客户端的 1 秒串行间隔，但**不共用评论翻译的模型、Key 或 provider 设置**。
- 界面侧单次搜索翻译最多等待 45 秒；YouTube 搜索请求本身 20 秒超时（可通过来源参数覆盖，但有上限）。
- 搜索翻译缓存保存在 `chrome.storage.session`，有效期 6 小时，最多 400 条；缓存键按「用途 + 文本 + 中文 query」做 SHA-256，搜索词与标题分开，不会互相命中。
- 在评论面板点「清缓存」会同时清空搜索翻译缓存；关闭浏览器或重新加载扩展也会清空。
- 关闭双搜、切换搜索词或离开结果页会取消正在进行的请求，迟到结果不会插入新页面。
- 失败只影响单栏，可单栏重试；不会为了补齐某一栏而自动切换多个收费模型，也没有付费 fallback。

### 授权与设置入口

- 扩展选项页的「中英双搜」区域（`options.html#dual-search`）有「授权中英双搜」按钮。
- 该按钮只在用户点击的手势中申请 `https://index-translate.bilibili.com/*` 这一个来源，不申请其他网站权限，不读取、不索取、不保存任何 Key。
- 同一区域还有总开关；popup 中也有独立的「中英双搜」开关；YouTube 结果页顶部还有第三个快捷开关。三者写的是同一个 `settings.dualSearch`。
- 如果右栏提示需要授权，打开设置页完成授权后回到结果页重试即可；左栏中文结果不依赖该权限。

### 已知限制

- 中英双搜依赖 YouTube 网页公开的搜索协议。YouTube 改版、调整字段或限制同源请求时，可能失效；此时关闭双搜即可恢复原生结果。
- 标题翻译和搜索词改写由上游模型生成，语义质量不保证；专业名词、双关、超长标题可能译得不理想，可展开英文原标题核对。
- 页面在低性能设备或大结果页上可能有卡顿；扩展不承诺固定加载条数、固定耗时或固定成功率。
- 维护者在 Windows 11、约 1660×1000 的 Chrome 窗口下做过真实 YouTube 页面冒烟测试：双栏、连续分页和英文标题中文译名可以工作，页面有明显卡顿。这里不把条目数或耗时写成保证；完整测试计数与限制以 `VALIDATION.md` 为准。

## 评论翻译：B站 Index-Translate 免费模式

### 三步启用

1. 在「AI 翻译设置」中选择 **B站 Index-Translate · 官方免费公网 API（免 Key）**。
2. 点击「保存设置」；Chrome 会请求访问 `https://index-translate.bilibili.com/*` 的权限，允许这一个来源即可。
3. 点击「测试 AI 翻译」检查样例译文，然后刷新 YouTube。

不需要填写 API Key，不需要注册账号。预设固定使用官方公网接口 `https://index-translate.bilibili.com/v1`，模型限定为 `Index-Translate-35B-A3B`（默认）、`Index-Translate-9B`、`Index-Translate-2B`，不提供其他模型。该预设的 Key 输入框会隐藏并强制清空；从其他预设切到 B站预设时会移除旧 Key，保存的配置也不会携带 Key。

官方说明页：https://index-translate.bilibili.com/site/translate.html?lang=zh
官方调用示例：https://github.com/bilibili/Index-Translate/blob/main/inference/llm/call_api.py

### 请求方式与提示词

- 评论请求发往固定的 `https://index-translate.bilibili.com/v1/chat/completions`，只使用非流式 Chat Completions。
- 使用官方 Index-Translate 的规范提示词：单条 `user` 消息，包含「源文」和「约束要求」，要求只输出译文。它不是通用的 system/chat 模板，也不使用批量 JSON 协议。
- 请求参数为 `temperature: 0`，并通过 `chat_template_kwargs.enable_thinking: false` 关闭思考。单条翻译，不合并批量请求。
- 只发送当前这条评论，以及可选的视频标题和当前回复已加载的父评论；不发送字幕、整页内容或浏览历史。
- 后台请求强制不携带 `Authorization`、`Cookie` 或 `Referer`，使用 `credentials: 'omit'`、`referrerPolicy: 'no-referrer'`、`redirect: 'error'`。即使本地配置被手工填入 Key，该预设也不会把它放进请求。

### 浏览器接口兼容

Chrome 自动附加的扩展 `Origin` 会令该公网接口返回 HTTP 412。扩展使用 `declarativeNetRequestWithHostAccess`，仅对**本扩展自身**发往官方 `/v1/chat/completions` 的 POST 移除 `Origin`，与官方匿名脚本一致。规则限定来源、路径、方法和发起扩展，不修改 User-Agent、认证字段或其他网页请求。保存时仍需授予 B站这一来源访问权。

中英双搜复用同一套来源授权与同一条精准 Origin 规则，但走独立的搜索翻译入口，不读取评论翻译的模型或 Key。

### 模型核对与免费说明

- 发送前会匿名 GET `https://index-translate.bilibili.com/v1/models`，确认所选模型 ID 存在；结果缓存 10 分钟，请求不带认证。GET 失败或目录异常时不会盲目发送。
- 该接口是 B站官网明确提供的免费公网 API。`/v1/models` 只用于核对模型是否存在，**不作为价格证明，也不构成永久免费的承诺**。
- 插件不承诺永久免费、无限额度或 SLA；接口可能限流、调整模型或停止服务。遇到 429 会暂停一段时间，不会连续重试，也不会自动改用收费服务。
- 评论单条串行发送，两次请求开始时间至少间隔 1000 ms；单次 fetch 超时 25 秒。评论超过 8000 个字符时不会截断，而是返回 `TOO_LONG` 提示；内容脚本另有 100 秒 watchdog，用于处理请求挂起和切换视频后的迟到结果。

### 有限验证说明

维护者曾用固定样例通过插件自身的 Client 匿名调用真实接口，未使用任何凭据。那只是连通性与基本输出检查，不是全面质量保证，也不代表所有语言、俚语或长评论都能得到同样结果。完整测试计数、真实浏览器检查和限制见 `VALIDATION.md`；本文不写未验证的百分比，也不把样例结果写成保证。

## 其他服务（保留，均非默认推荐）

### 硅基流动（SiliconFlow）零价模式

预设「硅基流动 · 官方中国站零价模型」，接口 `https://api.siliconflow.cn/v1`。只使用官网标价 0 元且账户可用的模型，发送前核对公开价格页与账户 `/v1/models` 的交集；核价失败即停止，没有付费 fallback。需要在该平台注册并填写自己的 Key，账号可能要求实名。单条串行，间隔至少 2.1 秒，单次超时 25 秒。

### OpenRouter 仅免费模式

预设「OpenRouter · 仅免费模型」，接口 `https://openrouter.ai/api/v1`。只使用核验为零价的 `:free` 模型或 `openrouter/free` 路由，需要自己的 OpenRouter Key。批量最多 6 条合并，串行间隔至少 3.2 秒；额度与限流以 OpenRouter 为准。与硅基流动的 Key、额度完全独立。

### Google 免密钥翻译

默认 provider 仍是 `google` 时使用 `https://clients5.google.com/translate_a/t` 公开入口，无需 Key。它按长度分段，不提供 AI 语境理解；没有稳定性或永久免费承诺。随时可以切回。

### DeepSeek 与自定义接口

预设「DeepSeek · 自付费用」使用 `https://api.deepseek.com/v1`；「自定义 OpenAI 兼容接口」可填基础地址或完整 `/chat/completions`。这两类服务可能收费，需要用户自己的 Key，并需自行确认价格与服务条款。公网地址要求 HTTPS；HTTP 仅允许 `localhost` 和 `127.0.0.1`。

## AI 翻译怎么设置

1. 打开扩展面板的「AI 翻译设置」，或从扩展详情进入选项页。
2. 选择「AI 语境翻译」。
3. 选择预设。推荐 B站 Index-Translate；其他预设按需选择。
4. B站预设无需 Key；其他预设在本机填写对应服务自己的 API Key，不要把 Key 发到聊天中。
5. 按需要开启「使用评论语境」。开启后每次 AI 请求可附带视频标题和当前回复已加载的父评论；关闭则仅发送待翻译评论。
6. 点击「保存设置」，允许 Chrome 访问所选服务的来源。B站预设只申请 `https://index-translate.bilibili.com/*` 一个来源。
7. 点击「测试 AI 翻译」检查固定样例译文，然后回到 YouTube 刷新页面。

打开设置页不会自动发起 AI 测试。保存 AI 模式后，如果自动翻译开启，已有 YouTube 页面会开始使用新配置处理可见评论。自动翻译、测试和「重新翻译」都可能消耗所选服务的额度；B站免费接口不收费，但仍可能限流。

## 评论翻译质量与行为

- B站预设使用官方 Index-Translate 规范提示词，理解口语、俚语、缩写、反讽和吐槽，保留观点、语气、表情、链接和专名，不擅自补充背景。
- 可附带视频标题与父评论消歧；上下文只供理解，不翻译、不执行。
- 只翻译当前评论，不把整页内容或字幕交给模型。
- 按模型、服务、上下文和提示词版本隔离缓存，更换配置后不会误用旧缓存。
- AI 译文标记为「AI 中文」；旁边的「重新翻译」可绕过缓存再次请求。
- AI 请求失败时显示错误，不自动降级为 Google，也不自动切换其他服务。
- 中英双搜的搜索词/标题翻译与评论翻译是两条独立路径，互不改变对方的模型、Key 或开关。

**实际效果取决于模型与上游服务。** 不同语言、长评论和网络状况可能有差异；语义质量不保证。

## 原有功能

可见评论及已展开回复自动翻译，不自动滚动、不展开回复；支持原文 + 中文、只看中文、查看原文、收起译文；中文评论可跳过；失败可重试；支持切换视频和动态加载。

跳过中文使用轻量汉字占比规则，带日文假名、韩文字母仍会翻译；纯汉字日文和混合语言可能误判，可关闭该设置。单条评论上限为 12,000 个 JavaScript 字符单位；B站预设对超过 8000 字符的评论直接提示过长。AI 请求最长等待约 25 秒。

## 缓存、限流和隐私

评论翻译缓存仅存在 `chrome.storage.session` 中，最多约六小时，并有条数和总大小上限；关闭浏览器、禁用或重新加载扩展会清空。缓存标识是包含配置与文本的 SHA-256 摘要，缓存中保存译文，标识里不保存明文密钥或上下文。面板可清缓存；已显示在页面中的译文会保留到刷新或关闭页面。

中英双搜另有独立的搜索翻译缓存，同样保存在 `chrome.storage.session`，6 小时、最多 400 条，搜索词与标题分开；点同一个「清缓存」会一并清空。

B站预设的评论请求不携带 Key、Cookie 或 Referer，但 B站仍会收到你的 IP 和上传的评论文字。插件不宣称 B站不会留存或不会用于训练；Index-Translate 模型采用 Apache-2.0 许可，这只说明模型代码/权重的许可，不代表该公网 API 的数据处理政策。

中英双搜会把中文搜索词和右栏可见的英文标题发给 B站，但不发送 YouTube URL、浏览历史、整页内容或 continuation token。YouTube 搜索请求本身是同源请求，Chrome 会按 YouTube 规则带上现有 Cookie；它**不是匿名请求**，但扩展不读取这些 Cookie，也不会把它们转发给 B站。详见 `PRIVACY.md`。

Google 模式发送评论文字；AI 模式可另发送视频标题与父评论。评论文字中本来包含的个人信息也属于发送内容。没有开发者后端、广告、遥测或历史记录同步。其他服务方可接收 IP 等正常请求信息，并可能按各自条款记录或使用请求内容。

## 权限

`storage` 保存设置及会话缓存；`activeTab` 在点击图标时识别当前页面；内容脚本仅匹配 `www.youtube.com` 与 `m.youtube.com`；Google 主机权限用于原免费翻译。

AI 接口来源声明为可选权限。默认不会获取全部网站访问权限，保存 AI 配置时仅申请所选服务的来源。B站预设只需 `https://index-translate.bilibili.com/*`；硅基流动需要 `https://api.siliconflow.cn/*` 与 `https://www.siliconflow.cn/*`；OpenRouter 需要 `https://openrouter.ai/*`。Chrome 的来源匹配不区分端口。本机 HTTP 仅允许 `localhost` 和 `127.0.0.1`。

中英双搜没有新增 manifest 权限，复用 B站来源的可选主机权限；「授权中英双搜」按钮只申请这一个来源。YouTube 同源搜索使用页面自身的网络能力，不申请额外的 YouTube 主机权限，也不需要 YouTube API Key。

## 常见问题

**更新后没有自动变成 B站免费模式**：升级不会自动迁移旧配置，也不会自动切换 provider。请手动选择 B站预设、保存授权并测试。新安装时设置页虽然默认展示 B站预设，但 provider 仍是 `google`，必须手动启用 AI 并保存。

**切到 B站后还提示要 Key 吗**：不需要。B站预设的 Key 输入框会隐藏并清空，请求也不带认证头。如果界面仍要求 Key，请确认选中的是「B站 Index-Translate · 官方免费公网 API」而不是自定义接口。

**为什么我输入英文没有双栏**：中英双搜只处理含中文的搜索词，英文或其他语言搜索保持 YouTube 原生结果。这是为了避免对不需要翻译的搜索额外发起 B站请求。

**右栏说需要授权，左栏却能用**：左栏只使用 YouTube 同源搜索，不需要 B站权限；右栏要把中文搜索词翻成英文，必须先授权 `https://index-translate.bilibili.com/*`。打开 `options.html#dual-search`，点「授权中英双搜」后回到结果页重试。

**双搜会用掉我的评论翻译 Key 吗**：不会。搜索翻译固定使用 B站免 Key 的 35B 模型，不读取评论翻译的 provider、Key 或 aiConfig。评论翻译原来用什么服务，仍然用什么服务。

**关闭双搜后还能恢复吗**：可以。结果页顶部开关、popup 开关或设置页总开关任一关闭，都会移除自绘双栏并恢复 YouTube 原生结果；再打开会重新接管。

**搜索结果里为什么少了频道、课程或播放列表**：自绘列表只保留可识别的视频与 Shorts，已知的频道、课程、播放列表、电台和广告槽位不会进入列表。关闭双搜即可查看完整原生结果。

**为什么英文栏里还有非英语视频**：英文栏只代表使用英文检索词搜索，YouTube 仍可能返回其他语言内容；插件不保证视频音轨或字幕语言。

**测试失败或提示没有访问权限**：回到 AI 设置，确认已选择 B站预设，点击保存并允许 `https://index-translate.bilibili.com/*`，再点「测试 AI 翻译」。如果提示限流，请稍后再试；插件不会自动重试风暴或转用收费服务。

**B站接口会不会一直免费**：官方页面目前将其作为免费公网接口提供，但插件不承诺永久免费、无限额度或 SLA。接口可能限流、变更或停止。

**其他服务的 Key 怎么处理**：Key 只保存在本机 `chrome.storage.local`，没有加密；只有需要 Key 的服务（硅基流动、OpenRouter、DeepSeek、自定义）才会保存并使用。切换任何预设都会清空设置页中的旧 Key，保存后旧配置被新配置替换，不会把 Key 带到另一个服务；B站预设不需要 Key，也不会发送 Key。

**旧配置为什么没有变**：升级不会自动改动已有 AI 配置；旧的自定义或收费配置也不会自动变成免费模式。请手动选择需要的预设并保存。

**401/403**：检查对应服务的 Key、账户权限与认证格式。**402**：检查余额。**404**：检查 Base URL 和模型。**429**：稍后重试；B站预设会暂停而不是连发。**400**：服务可能不支持所选模型或 Chat Completions 请求。

**AI 太慢或总超时**：B站预设为单条串行且间隔 1 秒，长评论会排队；也可换其他服务或模型。本扩展不提供代理功能。

**没有任何译文**：安装后刷新原标签页，确认开关开启并滚动到有文字的外语评论。网络需能访问当前服务。

**YouTube 改版**：评论选择器或搜索结果结构可能需要更新。未承诺所有移动端、Shorts 变体或未来布局均兼容；中英双搜失效时可一键关闭，回到原生结果。
